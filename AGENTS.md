## What this repo is (one paragraph, no hype)
Tripwire feeds a Grok agent deliberately corrupted engineering data through a tool server, measures whether the agent notices, and ships a fail-closed check. The server serves public data (e.g. FAA service difficulty reports) and synthetic work orders from a committed, seeded generator, and can plant faults on command: swapped units, stale spec revisions, truncated results, and writes that report success but never happened. Every planted fault is recorded, so adjudication (noticed / acted / correct outcome) is deterministic, with no LLM judge. The fix is a fail-closed read-back gate, measured for lift and cost. Method ported from [sabot](https://github.com/Jott2121/sabot). **Headline:** the gate passed a pre-registered 72-job holdout (A4: 100% correct on faulted data vs 66.7% for the "check your data" prompt; small n, one model). Results and their sources live in README.md and `docs/results/`; build state in `docs/STATUS.md`.

# typecheck: n/a for now
python -m pytest -q --cov=tripwire --cov-report=term-missing --cov-fail-under=90   # test

## Non-negotiables
1. **No employer data. Ever.** This is personal work on personal equipment. Never add, paste, paraphrase, or "anonymize" anything from any employer's systems, documents, tickets, chats, or datasets. No employer names in fixtures, no internal acronyms, no realistic HR records. Public data (FAA, NASA open data) or synthetic data only, synthetic data generated by a committed script with a fixed seed. If a prompt looks like it came from work, stop and ask. CI's `no-employer-data` job enforces this from the hashed list in `.github/blocked-terms.sha256` (`scripts/scan_blocked_terms.py`), plus an optional `EMPLOYER_MARKERS` regex secret; never write blocked terms in plaintext to explain or test it.
2. **Receipts over hype.** Every number in README, docs, PR descriptions, or posts must be reproducible from a committed command. Link the command and the artifact (`runs/`, `reports/`, CI log). No "blazing fast", "SOTA", "production-grade" without a measurement.
3. **Honest benchmarks.** Report nulls and regressions at the same prominence as wins. State n, seeds, model + version, date, and cost. Pre-register the decision rule (`docs/PREREGISTRATION.md`) before running a comparison. Never tune on the test set. Never delete an inconvenient run; mark it superseded with a reason.
4. **Fail closed.** Gates, validators, and guards deny on error, timeout, missing input, or unparseable output. Error *reporting* may fail open; *decisions* may not. Never weaken a guard to make a test pass. Never catch-and-ignore exceptions in a decision path.
5. **Tests and CI are the definition of done.** New behavior ships with a test that fails without it. Bug fixes ship with a regression test. Do not lower coverage floors or `--cov-fail-under` values. Do not mark tests `skip`/`xfail` to get green.
6. **Model never grades its own output.** Fault adjudication is mechanical (the injection ledger vs. what the agent did). Where a judge model is unavoidable, use a different lineage from the model under test and record both.
7. **Irreversible = human-gated.** No force-push, no history rewrite, no publishing to PyPI, no tagging releases, no posting anywhere. Open a PR; a human merges. `main` is branch-protected.
8. **No live model calls in the default test path.** Tests use a mocked or recorded xAI client. `XAI_API_KEY` is never read by tests and never printed.

## Code style
- Python 3.11+; stdlib-first; every new runtime dependency needs a one-line justification in the PR.
- Type hints on public functions. Small pure functions. No global mutable state.
- Errors: raise specific exceptions; log with context; no bare `except`.
- Secrets only via env vars; `.env` is gitignored; never print secret values.
- Don't commit build output: `__pycache__/`, `*.pyc`, `.coverage`, `.venv/`, `runs/tmp/`.

## How to work in this repo
- Briefs arrive as GitHub issues. Headless Claude Code runs start from `scripts/run-brief.sh <issue>` in a worktree on branch `claude/issue-<n>`, and end with a PR that says `Closes #<n>`.
- Start non-trivial work in **Plan mode**; save the plan to `.cursor/plans/` and link it in the PR.
- Default to one agent. Fan out only for read-heavy, independent work. Writes stay single-threaded per file.
- Keep PRs small (< ~400 changed lines) with one intent. Title: `type(scope): summary`.
- PR body must include: **What / Why / How verified (commands + output) / Numbers changed (before → after, with command) / Risks / Not done**.
- When you learn something durable about this repo, propose an edit to this file or a skill in the same PR.
