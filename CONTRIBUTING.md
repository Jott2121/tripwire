# Contributing to tripwire

This is a personal research project, but issues and pull requests are welcome. The full agent and
contributor rules live in [AGENTS.md](AGENTS.md); this is the short version.

## Ground rules

1. **Public or synthetic data only.** Never add, paste, or paraphrase data from any employer's
   systems, documents, or datasets. Fixtures are synthetic, generated by a committed seeded script.
   CI's `no-employer-data` job scans every tracked file and fails closed.
2. **Receipts over hype.** Every number in the README, docs, or a PR must be reproducible from a
   committed command, with the command and artifact linked. Report nulls and regressions as
   prominently as wins.
3. **Fail closed.** Gates, validators, and the budget ledger deny on error, timeout, or missing
   input. Never weaken a guard to make a test pass.
4. **Tests are the definition of done.** New behavior ships with a test that fails without it. Do
   not lower the coverage floor or mark tests `skip`/`xfail` to get green.
5. **No LLM judge.** Fault adjudication is mechanical (the injection ledger vs. what the agent did).

## Setup

```bash
python -m venv .venv && . .venv/bin/activate
pip install -e ".[dev]"
```

## Before you open a PR

Run the same checks CI runs:

```bash
make check
```

which is:

```bash
ruff check . && ruff format --check .
python -m pytest -q --cov=tripwire --cov-fail-under=90
python scripts/scan_blocked_terms.py
```

Keep PRs small (< ~400 changed lines) and single-intent. Title them `type(scope): summary`. The PR
body should cover **What / Why / How verified (commands + output) / Risks / Not done**. A human
merges; `main` is branch-protected — no force-pushes, tags, or history rewrites.
