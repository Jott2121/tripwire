# Data: FAA Service Difficulty Reports (SDRs)

Tripwire's first public data source is the FAA Service Difficulty Reporting
System (SDRS). SDRs are operator- and mechanic-submitted reports of mechanical
problems found on aircraft.

## Source

- Download page: https://www.faa.gov/av-info/download_SDR
- Annual CSV file pattern: `https://external.apic4e.faa.gov/sdrs/retrieve/SDR-<year>.csv`
  (e.g. `SDR-2026.csv`). Fetch one with `PYTHONPATH=. python3 scripts/fetch_sdr.py --year 2026`.
- Field layout (Batch File Layout): https://sdrs.faa.gov/Documents/Batch%20File%20Layout.pdf
- JASC codes: https://sdrs.faa.gov/documents/JASC_Code.pdf

## Format

- Encoding: UTF-8. The committed profile `reports/sdr_profile_2026.json`
  (`scripts/profile_sdr.py` on `SDR-2026.csv`, 45,910 rows, 2026-10-11) found
  0 decode errors under UTF-8 and 151 under cp1252. The loader fails closed
  with `SDRFormatError` (naming the byte offset) on any byte that is not valid
  UTF-8. The FAA file itself contains some pre-existing mis-encoded text (e.g.
  a stray `Â°`); later stages must not treat that as loader damage.
- 76 columns, in the order recorded in `tripwire/sdr.SDR_COLUMNS` (77 is the
  separate batch *upload* layout, not the download). The header line is
  reproduced below; the loader maps columns by name and reads each file's own
  header, so a file with an extra column still loads, with required columns
  matched by name:

  `OperatorControlNumber,DifficultyDate,SubmissionDate,OperatorDesignator,SubmitterDesignator,SubmitterTypeCode,ReceivingRegionCode,ReceivingDistrictOffice,SDRType,JASCCode,NatureOfConditionA,NatureOfConditionB,NatureOfConditionC,PrecautionaryProcedureA,PrecautionaryProcedureB,PrecautionaryProcedureC,PrecautionaryProcedureD,StageOfOperationCode,HowDiscoveredCode,RegistryNNumber,AircraftMake,AircraftModel,AircraftSerialNumber,AircraftTotalTime,AircraftTotalCycles,EngineMake,EngineModel,EngineSerialNumber,EngineTotalTime,EngineTotalCycles,PropellerMake,PropellerModel,PropellerSerialNumber,PropellerTotalTime,PropellerTotalCycles,PartMake,PartName,PartNumber,PartSerialNumber,PartCondition,PartLocation,PartTotalTime,PartTotalCycles,PartTimeSince,PartSinceCode,ComponentMake,ComponentModel,ComponentName,ComponentPartNumber,ComponentSerialNumber,ComponentLocation,ComponentTotalTime,ComponentTotalCycles,ComponentTimeSince,ComponentSinceCode,FuselageStationFrom,FuselageStationTo,StringerFrom,StringerFromSide,StringerTo,StringerToSide,WingStationFrom,WingStationFromSide,WingStationTo,WingStationToSide,ButtLineFrom,ButtLineFromSide,ButtlineTo,ButtlineToSide,WaterLineFrom,WaterLineTo,CrackLength,NumberOfCracks,CorrosionLevel,StructuralOther,Discrepancy`

- Dates: `DifficultyDate` is `MM/DD/YYYY` (e.g. `01/02/2026`). `SubmissionDate` is
  an ISO-8601 timestamp with a UTC offset (e.g.
  `2026-01-02T14:09:41.140-05:00`), so it parses timezone-aware.

## Units

Units are sourced in `docs/MEASUREMENT_STANDARDS.md`, the repo's units
reference. For the fields Tripwire parses:

- `CrackLength` (`crack_length_in`): inches, per the SDRS Single Submission
  instructions (see `docs/MEASUREMENT_STANDARDS.md`). The `UNIT_SWAP`
  corruption's inches->millimetres factor 25.4 follows from that unit.
- `AircraftTotalTime` (`aircraft_total_time_hours`): hours, per the SDRS Field
  Instructions (see `docs/MEASUREMENT_STANDARDS.md`). The `UNIT_SWAP`
  corruption's hours->minutes factor 60 follows from that unit. Every hour
  column in the `SDR-2026.csv` profile is 100% whole numbers.
- `AircraftTotalCycles` (`aircraft_total_cycles`): a dimensionless count of
  flight cycles.

If `docs/MEASUREMENT_STANDARDS.md` changes a unit, update the corruption
factors together with it.

## Rights and redistribution

SDR data is published by the FAA, a US government agency. However, the narrative
`Discrepancy` text is operator-submitted, and redistribution rights for that
free text are unverified. Therefore:

- **No real SDR rows are ever committed to this repository.** Raw downloads go
  to `data/raw/` (gitignored). The committed fixtures are **synthetic**,
  generated by `tripwire/synth.py` from a fixed seed using the real header with
  fictional makes, operators, and part data only (e.g. `ACME AERO`, `OP01`). No
  real company, operator, or person names appear anywhere. Synthetic rows follow
  the code values observed in the real file (`SDRType` A/G, the observed
  `SubmitterTypeCode` set, two-letter `StageOfOperationCode`) and its
  control-number shape (fictional designator `TWSY` + `YYYYMMDD` + 4-digit
  sequence), with whole-number totals and `N`-less registration marks.

# Data: FAA aircraft registry (phase two)

Phase two (`docs/PREREGISTRATION-phase2-real-data.md`) joins SDRs to the FAA's releasable
aircraft database by N-number.

- Download: https://registry.faa.gov/database/ReleasableAircraft.zip (comma-delimited text
  files). Fetch with `PYTHONPATH=. python3 scripts/fetch_registry.py`; it extracts only
  `MASTER.txt` and `ACFTREF.txt` to `data/raw/registry/` (gitignored) and writes
  `data/manifest/registry.json`. The site sometimes refuses the script (HTTP 403, seen
  2026-11-01). Then download the zip in a browser and run
  `PYTHONPATH=. python3 scripts/fetch_registry.py --from-zip ~/Downloads/ReleasableAircraft.zip`:
  same files, same manifest, plus `source_file`. The script never changes its client identity
  to get past a refusal.
- Layout: https://registry.faa.gov/database/ardata.pdf. `tripwire/registry.py` maps columns by
  name and accepts both that document's field names and the text files' short headers; a header
  matching neither fails closed. The header of the current download is confirmed by
  `scripts/profile_registry.py` (counts only, safe to commit).
- **Observed in the first real download (2026-11-01, `reports/registry_profile.json`).**
  318,181 master rows, no rejects, no duplicate N-numbers; 94,161 reference rows, one reject (a
  code that is not 7 characters). The master header is the text-file spelling (`N-NUMBER`,
  `SERIAL NUMBER`, `YEAR MFR`, ...), with one name padded (` KIT MODEL`) and a trailing empty
  column; both reference and master headers end in an empty column. 49,072 of 49,860 SDR-2026
  rows join by N-number.
- **Field shapes that matter for mining** (from `reports/sdr_profile_2026.json`): the SDR
  `AircraftMake` is a 3 to 6 letter code, not a name, and `AircraftSerialNumber` is digits only
  in about 99% of rows (up to 11 characters), while registry serials carry letters and run to 30
  characters. `mine-v1` and later compare accordingly (`tripwire/mining.py`).
- **Personal data.** The master file carries registrants' names and street addresses. The loader
  never reads those columns, and its record type has no field for them. Nothing from the master
  file but counts is ever committed.
- The FAA hosts are not reachable from the build container, so fetching and profiling are owner
  steps on a local machine.
